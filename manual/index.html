CarCare — Manual Técnico do Desenvolvedor

Documentação arquitetural, operacional e guia prático para desenvolvedores manterem e expandirem o ecossistema CarCare.

O CarCare é um aplicativo completo construído em Flutter e Dart, desenhado para gerenciamento abrangente de manutenção veicular para carros e motocicletas. O produto integra persistência em nuvem em tempo real com o Google Firebase (Authentication e Cloud Firestore) e consulta direta aos valores médios de mercado via API da Tabela FIPE.

2. Objetivo e Público-Alvo

Objetivo do Software

Eliminar o esquecimento de manutenções preventivas, monitorar o consumo real de combustível por quilômetro rodado e centralizar os custos com o veículo, emitindo alertas inteligentes conforme a quilometragem atual avança em relação aos limites de troca de óleo, freios, filtros, transmissão e pneus.

Público-Alvo

  • Proprietários individuais de carros e motos que desejam controle preventivo de custos.
  • Motoristas de aplicativo e entregadores que necessitam de acompanhamento rigoroso de consumo e trocas periódicas.
  • Entusiastas e gestores de pequenas frotas domésticas.

3. Tecnologias Utilizadas

Flutter & Dart

Framework multiplataforma (Android, iOS, Web, Windows) com arquitetura reativa Material 3.

Firebase Auth

Autenticação segura de usuários por e-mail e senha, com validação de credenciais e recuperação de acesso.

Cloud Firestore

Banco NoSQL em tempo real, modelado com isolamento estrito por usuário (users/{uid}/...).

API Tabela FIPE

Integração REST com a API pública FIPE (Parallelum) para marcas, modelos, anos e valor venal atualizado.

4. Requisitos para Executar o Projeto

  • Flutter SDK: versão 3.19 ou superior (testado com Flutter 3.47 / Dart 3.13).
  • Git: para versionamento e controle de branches.
  • Navegador Google Chrome (para execução web rápida) ou Android Studio / VS Code com emulador/aparelho físico.
  • Node.js & Firebase CLI (para comandos do FlutterFire): npm install -g firebase-tools.

5. Passo a Passo para Instalação

  1. Clone ou abra o repositório no seu computador: 
    git clone <url-do-repositorio>
cd carcare
  2. Instale todas as dependências do Flutter: 
    flutter pub get
  3. Execute o projeto no navegador ou emulador: 
    flutter run -d chrome

6. Configuração do Firebase

O projeto já possui os arquivos pré-configurados pela CLI oficial (flutterfire configure). Caso precise conectar a outro projeto Firebase do zero:

  1. Acesse o Console do Firebase e crie um projeto (ex: meu-carcare).
  2. Ative o Authentication → Sign-in method → E-mail/senha.
  3. Crie o Firestore Database no modo de produção, na região southamerica-east1 (São Paulo).
  4. Na aba Regras (Rules) do Firestore, copie e cole o conteúdo do arquivo firestore.rules do projeto e clique em Publicar.
  5. No terminal, configure as credenciais da aplicação executando: 
    dart pub global run flutterfire_cli:flutterfire configure

8. Estrutura do Banco de Dados (Cloud Firestore)

Cada usuário autenticado possui sua própria árvore de dados privada, garantindo total isolamento e segurança:

Caminho da Coleção Campos Principais Finalidade
users/{uid} name, email, createdAt Perfil e dados do motorista autenticado.
users/{uid}/vehicles/{id} type ('carro'|'moto'), brand, model, year, plate, currentKm, transmission, fipeCode, fipeValue, fipeReference, createdAt Veículos cadastrados pelo usuário.
users/{uid}/maintenances/{id} vehicleId, category, date, km, cost, notes, nextKm, nextDate, createdAt Histórico de manutenções e projeção de serviços futuros.
users/{uid}/fuel/{id} vehicleId, date, km, liters, totalPrice, createdAt Abastecimentos para cálculo de consumo e custo por litro.

9. Regras de Segurança (firestore.rules)

O arquivo firestore.rules implementa validação estrita:

  • Isolamento Total: apenas request.auth.uid == {uid} tem permissão de leitura e escrita. Nenhuma informação é visível para outros usuários.
  • Validação de Schema: proíbe campos inesperados (hasOnly) e checa tipos de dados (números não negativos, limites de texto).
  • Imutabilidade de Auditoria: o campo createdAt não pode ser modificado após a criação.

10. Explicação do Login e Cadastro

A navegação inicial é governada pelo AuthGate (StreamBuilder ouvindo authStateChanges):

  • Login: valida campos de e-mail e senha com feedback imediato. Se as credenciais estiverem incorretas, exibe card de erro estilizado em português (ex: "E-mail ou senha incorretos"). Inclui recuperação de senha via e-mail.
  • Cadastro: solicita Nome, E-mail, Senha e Confirmação de senha. Garante consistência de senha igual e salva o perfil no Firestore e Firebase Auth simultaneamente.

11. Tela Principal (Home)

A tela inicial dispõe de barra de navegação responsiva em 4 abas:

  1. Início (Visão Geral): exibe saudação ao motorista, cards de resumo (total de veículos, gastos do mês, consumo médio geral, quantidade de alertas pendentes) e os alertas mais urgentes.
  2. Veículos: listagem dos carros e motos com quilometragem, placa, valor FIPE e badge de manutenções pendentes.
  3. Manutenções: histórico completo com filtro por veículo, custos e indicação visual de serviços.
  4. Abastecimentos: histórico com volume abastecido, preço pago e cálculo de preço por litro.

12. Como Cadastrar, Editar e Excluir Informações (CRUD)

Veículos

  • Criar: toque no botão + Novo Veículo na aba Veículos. Escolha entre Carro ou Moto, informe marca, modelo, ano, quilometragem inicial e placa. Para carros, selecione o tipo de câmbio (Manual ou Automático).
  • Consultar: toque no card do veículo para abrir a folha com todos os detalhes e acessar a consulta FIPE.
  • Editar: na folha de detalhes, toque em Editar para atualizar qualquer campo.
  • Atualizar KM Rápido: na folha de detalhes, toque em Atualizar ao lado do odômetro.
  • Excluir: na folha de detalhes, toque em Excluir. O sistema realiza exclusão em cascata (remove o veículo e todas as manutenções e abastecimentos vinculados via WriteBatch).

13. Manutenções, Catálogo e Alertas Futuros

O aplicativo adapta o catálogo de serviços conforme o tipo de veículo:

Catálogo para Moto

Óleo do motor e filtro, freios, pneus/rodas, kit de transmissão, sistema elétrico, velas/filtro de ar, revisões periódicas, óleo das bengalas, caixa de direção, balança traseira, arrefecimento, radiador, cabos de aço, manetes/pedal, filtro de combustível e TBI.

Catálogo para Carro

Troca de óleo e filtro, revisão geral, pneus, filtros de ar e combustível, freios, alinhamento/balanceamento, fluidos, sistema elétrico, suspensão/escape, correia dentada, velas/cabos, transmissão, embreagem (apenas para carros manuais) e palhetas.

Ao registrar um serviço, o app calcula a projeção do próximo serviço (por quilometragem e por data). Se o veículo atingir o limite ou estiver a menos de 500 km / 15 dias, o status passa para Em breve ou Atrasado com badges vermelhas na tela inicial.

14. Abastecimento e Consumo Médio

Ao registrar abastecimentos com a quilometragem atual e a quantidade de litros, o CarCare calcula o consumo médio em km/l considerando a distância percorrida entre abastecimentos consecutivos dividida pelos litros consumidos.

15. Como Alterar Cores (Identidade Visual)

Amarelo Pólen de Ouro #E8B004 (Destaques e Ações)
Branco Gelo #F7F7F2 (Fundo Modo Claro)
Obsidian Black Metallic #121214 (Fundo Modo Escuro)

Todas as cores da aplicação estão centralizadas em um único arquivo: lib/theme/app_colors.dart:

// lib/theme/app_colors.dart
class AppColors {
  static const Color goldenPollen = Color(0xFFE8B004); // Mude aqui para alterar a cor primária
  static const Color iceWhite     = Color(0xFFF7F7F2); // Mude aqui para alterar o fundo claro
  static const Color obsidian     = Color(0xFF121214); // Mude aqui para alterar o tema escuro
}

Qualquer modificação refletirá automaticamente em botões, abas, ícones e temas.

16. Como Trocar o Logo

  1. Gere uma nova imagem quadrada (PNG, recomendado 1024x1024 px).
  2. Substitua o arquivo em assets/images/logo.png.
  3. Copie também para manual/imagens/logo.png para atualizar o manual.
  4. Para recriar os ícones do aplicativo para Android, iOS, Web e Windows, execute no terminal: 
    flutter pub run flutter_launcher_icons

17. Como Alterar o Nome do Aplicativo

  1. No código Flutter: abra lib/utils/constants.dart e altere a constante: 
    const String appName = 'NovoNome';
  2. No Android: em android/app/src/main/AndroidManifest.xml, altere: 
    android:label="NovoNome"
  3. Na Web: em web/index.html, altere a tag <title> e a meta tag apple-mobile-web-app-title.

18. Como Adicionar ou Alterar uma Tela

  1. Crie o arquivo em lib/screens/nome_da_tela_screen.dart estendendo StatelessWidget ou StatefulWidget.
  2. Use Scaffold com AppBar e envolva o corpo em ResponsiveCenter ou pagePadding(context) para manter o padrão responsivo.
  3. Para navegar para ela a partir de qualquer botão, utilize o Navigator padrão do Flutter: 
    Navigator.push(
  context,
  MaterialPageRoute(builder: (context) => const MinhaNovaTelaScreen()),
);

19. Como Adicionar ou Alterar um Campo no Banco de Dados

Por exemplo, para adicionar o campo chassi em Veículos:

  1. No Modelo (lib/models/vehicle.dart): adicione a propriedade final final String chassi;, inclua no construtor, no método toMap() e no construtor de fábrica fromDoc().
  2. Nas Regras (firestore.rules): adicione o campo 'chassi' na lista de chaves permitidas e a validação de tipo correspondente dentro de isValidVehicle. Publique as regras no Firebase Console.
  3. No Formulário (lib/screens/home/home_screen.dart): adicione o TextEditingController e o campo AppTextField correspondente dentro do _VehicleFormSheetState.

20. Como Gerar uma Nova Versão do Projeto (Build)

  1. Abra o pubspec.yaml e incremente a versão: 
    version: 1.0.1+2   # (versão visível + número do build)
  2. Para gerar o pacote de produção para Web: 
    flutter build web --release
  3. Para gerar o instalador do Android (APK): 
    flutter build apk --release
    O arquivo final estará localizado em: build/app/outputs/flutter-apk/app-release.apk.
  4. Para gerar o instalador para Windows Desktop: 
    flutter build windows --release

21. Solução de Problemas Comuns (Troubleshooting)

Erro: "permission-denied" no Firestore

Ocorre quando as regras de segurança ainda não foram publicadas no Firebase Console. Acesse o Console → Firestore Database → Regras, cole o conteúdo de firestore.rules e clique em Publicar.

Aviso: "flutterfire não é reconhecido"

Adicione o diretório global do Pub ao PATH do Windows: %LOCALAPPDATA%\Pub\Cache\bin e reabra o terminal.

Caminhos com espaço no Windows ("Área de Trabalho")

No Android, caso o Gradle acuse incompatibilidade com caracteres acentuados no diretório do projeto, adicione android.overridePathCheck=true no arquivo android/gradle.properties.
