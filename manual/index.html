CarCare — Manual Técnico do Desenvolvedor

Documentação arquitetural, operacional e guia prático para desenvolvedores manterem, publicarem e expandirem o ecossistema CarCare.

O CarCare é um produto de software construído com Flutter e Dart, desenhado para gerenciamento preventivo e controle de custos de carros e motocicletas. O sistema integra persistência em nuvem em tempo real com o Google Firebase (Authentication e Cloud Firestore), consulta em tempo real à API da Tabela FIPE, relatórios analíticos em gráficos de colunas, diário de bordo e alertas municipais de rodízio veicular.

2. Objetivo e Público-Alvo

Objetivo do Software

Eliminar o esquecimento de manutenções preventivas, monitorar o consumo real de combustível por quilômetro rodado (km/l ou km/m³ no GNV), centralizar os custos operacionais do veículo e emitir alertas inteligentes conforme o odômetro avança em relação aos limites de troca de óleo, freios, filtros, transmissão e pneus.

Público-Alvo

  • Proprietários individuais de carros e motos que desejam controle preventivo de custos.
  • Motoristas de aplicativo e entregadores que necessitam de acompanhamento rigoroso de consumo e trocas periódicas.
  • Entusiastas e gestores de veículos que buscam histórico unificado e valorização do patrimônio.

3. Tecnologias Utilizadas

Flutter & Dart

Framework multiplataforma (Android, iOS, Web, Windows) com arquitetura reativa Material 3.

Firebase Auth

Autenticação segura de usuários por e-mail e senha, com validação de credenciais e recuperação de acesso.

Cloud Firestore

Banco NoSQL em tempo real, modelado com isolamento estrito por usuário (users/{uid}/...).

API Tabela FIPE

Integração REST com a API pública FIPE (Parallelum) para marcas, modelos, anos e cotação de mercado atualizada.

4. Requisitos para Executar o Projeto

  • Flutter SDK: versão 3.19 ou superior (testado com Flutter 3.47 / Dart 3.13).
  • Git: para versionamento e controle de código.
  • Navegador Google Chrome (para execução web rápida) ou Android Studio / VS Code com emulador/aparelho físico.
  • Node.js & Firebase CLI (opcional): npm install -g firebase-tools.

5. Passo a Passo para Instalação

  1. Clone ou abra o repositório no seu computador: 
    git clone <url-do-repositorio>
cd carcare
  2. Instale todas as dependências do Flutter: 
    flutter pub get
  3. Execute o projeto no navegador Chrome: 
    flutter run -d chrome
    (Dica no Windows: use o atalho .\run na raiz do projeto)

6. Configuração do Firebase

O projeto já possui os arquivos pré-configurados pela CLI oficial (firebase_options.dart). Caso precise conectar a outro projeto Firebase:

  1. Acesse o Console do Firebase e crie um projeto (ex: car-care-5c6cf).
  2. Ative o Authentication → Sign-in method → E-mail/senha.
  3. Crie o Firestore Database no modo de produção, na região southamerica-east1 (São Paulo).
  4. Na aba Regras (Rules) do Firestore, publique o conteúdo de firestore.rules.
  5. Execute a CLI oficial do FlutterFire: 
    dart pub global run flutterfire_cli:flutterfire configure

7. Como Rodar e Publicar na Web (Vercel / Firebase Hosting)

Ao compilar o Flutter para web, ele gera arquivos estáticos puros (HTML, JavaScript, WebAssembly e assets) na pasta build/web. Isso significa que o aplicativo pode ser hospedado na Vercel, Firebase Hosting, Netlify ou GitHub Pages e funcionará em qualquer celular ou computador com internet sem precisar instalar nada na loja de aplicativos!

Deploy na Vercel (Passo a Passo)

  1. Gere os arquivos de produção para Web: 
    flutter build web --release
  2. Suba o projeto para o GitHub ou instale a CLI da Vercel: 
    npm install -g vercel
  3. No painel da Vercel (vercel.com):
    • Clique em Add New → Project e importe seu repositório do GitHub.
    • Em Build and Output Settings:
      • Output Directory: defina como build/web
      • Build Command: deixe em branco (se você já fez o build local) ou use um script com o Flutter SDK configurado.
    • Clique em Deploy.
  4. Pronto! Você receberá um link HTTPS gratuito (ex: carcare.vercel.app) que abre perfeitamente em navegadores mobile (Android, iOS Safari, Chrome, Edge) com sincronização em nuvem pelo Firebase.

9. Estrutura do Banco de Dados (Cloud Firestore)

Cada motorista possui sua árvore privada e criptografada em nuvem, garantindo isolamento total:

Coleção Campos Principais Descrição
users/{uid} name, email, createdAt Dados cadastrais do motorista autenticado.
users/{uid}/vehicles/{id} type ('carro'|'moto'|'caminhao'), brand, model, year, plate, currentKm, transmission, tankCapacity, ipvaDueMonth, ipvaPaid, ipvaAmount, licensingPaid, insuranceCompany, insurancePolicy, insurancePhone, insuranceExpiryDate, lastTireRotationKm, tireRotationIntervalKm, fipeCode, fipeValue, fipeReference, createdAt Carros, motocicletas e caminhões do usuário com controle de documentos e pneus.
users/{uid}/maintenances/{id} vehicleId, category, date, km, cost, notes, nextKm, nextDate, createdAt Registros de manutenção com projeção futura de revisão e odômetro anterior visível.
users/{uid}/fuel/{id} vehicleId, fuelType ('Gasolina'|'Etanol'|'Diesel'|'GNV'), date, km, liters, totalPrice, isFullTank (bool), gasStation (string), createdAt Abastecimentos completos com posto, tanque cheio/parcial, calculadora e rotina.

10. Regras de Segurança (firestore.rules)

As regras protegem as subcoleções exigindo autenticação do proprietário:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
      match /{allSubcollections=**} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}

11. Explicação do Login e Cadastro

  • AuthGate: escuta ativamente o estado de autenticação via stream. Usuários deslogados são direcionados ao Login; usuários autenticados vão direto para a tela principal.
  • Login: valida campos de e-mail e senha com feedback visual em português e suporte à recuperação de senha por e-mail.
  • Cadastro: cria a credencial no Firebase Authentication e grava simultaneamente o documento do motorista em users/{uid}.

12. Tela Principal (Home) e as 5 Abas

O aplicativo organiza toda a experiência em 5 abas integradas:

  1. Início (Visão Geral): cartões de resumo (veículos, gastos no mês, alertas de serviços ativos, consumo médio geral, média diária de distância), termômetro visual, radar de serviços automotivos próximos via Google Maps e banner de alerta se hoje for dia de rodízio.
  2. Veículos: listagem de carros, motos e caminhões com odômetro, placa, valor FIPE, chip de rodízio, botão de Lembretes & Documentos (IPVA, Licenciamento, Seguro, Pneus) e acesso ao Diário de Bordo.
  3. Manutenções: histórico de revisões com odômetro anterior visível, filtro por veículo, badge de status e botão para Editar ou Excluir.
  4. Abastecimentos: histórico com Card de Rotina de Abastecimento, botão para o Histórico de Postos Frequentados, calculadora automática de 3 campos, opção de Tanque Cheio vs Parcial e botão para Editar ou Excluir.
  5. Relatórios: gráficos de colunas interativos por Semana, Mês ou Ano, filtro por Carros, Motos e Caminhões, detalhamento clicável de custos e consumo médio com média diária de km.

13. Gestão de Veículos, Caminhões, FIPE & Rodízio Municipal

Suporte Completo a Caminhões

O sistema suporta oficialmente Carros, Motos e Caminhões. Para caminhões, o CarCare consulta a Tabela FIPE no endpoint /caminhoes, adota regras de rodízio ZMRC (Zona de Máxima Restrição de Circulação em SP das 05h às 21h em dias úteis) e calibra o termômetro de consumo para médias de diesel pesado (2.0 a 4.5 km/l).

Alerta Automático de Rodízio por Placa

O utilitário RodizioHelper lê o último dígito numérico da placa (funciona tanto no padrão tradicional ABC-1234 quanto no Mercosul ABC1D23):

  • Finais 1 e 2: Segunda-feira
  • Finais 3 e 4: Terça-feira
  • Finais 5 e 6: Quarta-feira
  • Finais 7 e 8: Quinta-feira
  • Finais 9 e 0: Sexta-feira
  • Motocicletas: Isentas de rodízio municipal.
  • Caminhões: Sujeitos ao rodízio de caminhões/ZMRC (05h às 21h).

Lembretes de IPVA, Licenciamento, Seguro & Rodízio de Pneus

Acessível em cada veículo pelo botão Lembretes: IPVA, Licenciamento, Seguro & Pneus:

  • IPVA: Mês de vencimento pelo final da placa, valor estimado com base na Tabela FIPE (4% carros, 2% motos, 1.5% caminhões) e botão de marcar como pago.
  • Licenciamento: Calendário oficial do Detran por final de placa com alertas de mês de vencimento.
  • Seguro do Veículo: Nome da seguradora, número de apólice, botão com ligação direta para assistência 24h/guincho e contagem regressiva de renovação.
  • Rodízio de Pneus: Quilometragem do último rodízio, intervalo recomendado (10.000 km), km restantes e barra de progresso visual de desgaste com botão de registro em 1 clique.

14. Manutenções, Alertas Futuros e Odômetro Anterior Visível

No formulário de manutenção, o motorista visualiza em destaque o último odômetro registrado, permitindo copiar o valor com 1 toque ou verificar quantos quilômetros foram rodados desde o serviço anterior.

Ao tocar em qualquer manutenção registrada, o usuário pode clicar no botão "Editar" para retificar custos, data, quilometragem ou observações caso tenha confirmado com algum erro.

15. Abastecimento, Calculadora Dinâmica, Tanque Cheio & Rotina

  • Calculadora Automática de 3 Campos: Conecta Preço por Litro/m³, Volume (Litros ou m³) e Valor Total (R$). Ao preencher 2 campos quaisquer, o 3º calcula instantaneamente sem necessidade de contas manuais.
  • Odômetro Anterior em Destaque: Exibe o último odômetro registrado e mostra um badge verde de quantos quilômetros foram rodados neste abastecimento.
  • Tanque Cheio vs Parcial: Chave seletora que define se o tanque foi completado. Abastecimentos com tanque cheio utilizam o método científico oficial para calcular o consumo exato daquele ciclo (km rodados ÷ litros consumidos).
  • Histórico de Postos Frequentados: Registra a bandeira/nome do posto (Shell, Ipiranga, BR, etc.), histórico de preços pagos e rota no Google Maps com 1 clique.
  • Card de Rotina de Abastecimento: Painel estatístico completo exibindo distância média entre abastecimentos, frequência em dias, autonomia estimada com tanque cheio, projeção mensal de gastos e a proporção de abastecimentos com tanque cheio.
  • Radar de Serviços Próximos (Google Maps): Botão de bússola no topo do app que abre buscas automáticas por postos de combustível, mecânicas, borracharias, autoelétricas e guinchos 24h na localização do usuário.

16. Termômetro Visual de Eficiência de Consumo

O widget ConsumptionThermometer classifica visualmente o consumo médio do veículo através de uma barra de 3 estágios com indicador dinâmico:

  • Verde (Muito Econômico): Alta autonomia por litro/m³.
  • Amarelo (Normal / Moderado): Consumo padrão esperado para a categoria.
  • Vermelho (Alto Consumo): Gasto elevado de combustível. Alerta o motorista para checar calibragem dos pneus, alinhamento, filtros e velas.

17. Gráficos de Colunas e Relatórios Financeiros

Localizado na aba Relatórios:

  • Gráficos por Período: escolha visualizar gastos por Semana (dias de Seg a Dom), Mês (4 semanas do mês atual) ou Ano (12 meses).
  • Colunas Coloridas: divisão proporcional e empilhada entre gastos de Combustível (Dourado) e Manutenções (Azul).
  • Interativo (Drill-Down): tocar em qualquer coluna abre o detalhamento exato com a lista de tudo o que foi gasto naquele período específico.
  • Tabela de Consumo: resumo da frota com litros abastecidos, consumo em km/l e avaliação do termômetro.

18. Diário de Bordo (Log Unificado do Veículo)

A tela VehicleLogScreen consolida a linha do tempo completa do carro ou moto. Ela reúne em ordem cronológica reversa todas as manutenções executadas, abastecimentos, evolução do odômetro e gastos acumulados com filtros rápidos (*Tudo*, *Serviços* e *Abastecimentos*).

21. Como Trocar o Logo

  1. Gere uma nova imagem quadrada (PNG 1024x1024 px).
  2. Substitua em assets/images/logo.png e manual/imagens/logo.png.
  3. Execute no terminal para recriar os ícones de todas as plataformas: 
    dart run flutter_launcher_icons

22. Como Alterar o Nome do Aplicativo

  1. No Flutter: altere appName em lib/utils/constants.dart.
  2. No Android: altere android:label em android/app/src/main/AndroidManifest.xml.
  3. Na Web: altere a tag <title> em web/index.html.

23. Como Adicionar ou Alterar uma Tela

Crie o arquivo em lib/screens/nome_da_tela_screen.dart e navegue utilizando:

Navigator.push(
  context,
  MaterialPageRoute(builder: (context) => const MinhaNovaTelaScreen()),
);

24. Como Adicionar ou Alterar um Campo no Banco de Dados

  1. Adicione a propriedade no Model (lib/models/...), construtor, toMap() e fromDoc().
  2. Adicione o campo correspondente no formulário da tela (_FuelFormSheetState, _VehicleFormSheetState, etc.).

25. Como Gerar uma Nova Versão do Projeto (Build)

  1. Incremente o número da versão em pubspec.yaml (ex: version: 1.0.1+2).
  2. Para Web: flutter build web --release
  3. Para Android APK: flutter build apk --release
  4. Para Windows Desktop: flutter build windows --release

26. Solução de Problemas Comuns (Troubleshooting)

Bloqueio de pasta no Windows / OneDrive ("Flutter failed to delete a directory at build\flutter_assets")

Ocorre quando um processo anterior do Dart fica preso ou o OneDrive segura a pasta aberta. Basta executar o script .\run na raiz do projeto ou rodar no PowerShell: Stop-Process -Name dart -Force; cmd /c "rmdir /s /q build".

Aviso: "flutterfire não é reconhecido"

Adicione %LOCALAPPDATA%\Pub\Cache\bin à variável PATH do sistema Windows.
